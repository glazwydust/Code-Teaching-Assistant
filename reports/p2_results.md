# P2 bug-type classifier: results

Model: one logistic regression per bug type (C = 16.0), on TF-IDF of the normalized code plus test-behaviour and structure features. Trained on 6392 generated bugs. Generated by `scripts/train.py`.

## Headline

| Test set | Programs | Top guess is right |
|---|---|---|
| Generated bugs, 5-fold CV split by base program | 6392 | 87% |
| Real programs, auto-labelled (confirmed by a passing fix) | 768 | 81% |
| Real programs, hand-labelled by Krishna (bug cases only) | 41 | 63% |

## Against the baselines (top guess is right)

| Method | Real, auto-labelled | Real, hand-labelled |
|---|---|---|
| always 'wrong_variable' | 4% | 17% |
| app.py text rules (before the model) | 25% | 22% |
| **trained model** | **81%** | **63%** |

## "Not sure"

A small second model (logistic regression on how far ahead the top bug type is, plus how the program behaved on the tests) estimates whether the top guess is right. It was trained on the 1067 auto-labelled real programs (never on the hand-labelled 50). Judged by 5-fold cross-validation it separates right from wrong guesses with AUC **0.89** (the top probability alone: 0.66). Cut-off: **0.500**; below it the app gives a general hint instead of naming a bug type.

| | Validation (auto-labelled) | Hand-labelled 50 |
|---|---|---|
| Programs answered | 58% | 36% |
| Answers that are right | 85% | 100% |
| 'other' programs where the model said not sure | 292/327 | 9/9 |
| Without 'not sure': answers right | - | 52% |

## Honesty notes

- Auto-labels come from the same kind of edits used to generate training bugs, so the auto-labelled score is optimistic; the hand-labelled 50 is the fairer test.
- 53 validation programs are identical (after renaming) to a training mutant; without them, real auto-labelled top-1 is 80%. Hand-labelled programs with a twin: 4.
- The hand-labelled set is small (50, of which 41 have a named bug), so its numbers move by 2-3 points per program.
- The JSON model used by the app matches scikit-learn to within 4.0e-06.
